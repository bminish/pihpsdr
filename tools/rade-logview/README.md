# RADE log viewer

Standalone viewer for the parameter logs piHPSDR writes (`rade-logs/<run>/`, or the `<run>.tar.gz` made when a run stops).
Needs Python 3 with tkinter, numpy and matplotlib (TkAgg); no piHPSDR running.

    python3 tools/rade-logview/rade_logview.py [run-directory | run.tar.gz | folder-of-runs ...]

- **Files…** (select several at once) any files in run directories and/or `.tar.gz`; **Folder…** a run directory, or a folder of runs (every run directory in it, and every `.tar.gz` whose directory is not there; when a folder holds several runs a list opens to choose from, all selected, shift/ctrl-click to narrow). **Remove** drops the selected run, **Remove all** clears the list. The same applies to the command line. Runs are drawn together (one colour each) on a UTC axis.
- **Live runs**: a run opened from a directory whose `meta.txt` has no `ended_utc` yet (the log is still being written) is marked ● in the list. **Update live (F5)** first opens the newest run directory in `rade-logs/` if it is not open already, then reloads the live runs whose files have changed (a line being written is ignored until it is complete), keeps the zoom, and, with **Follow the newest data** ticked, moves the right edge to the newest data at the same width. **every N s** does this automatically (1-60 s, off by default). A run that has ended stops being live. A `.tar.gz` is never live.
- **Parameters**: each ticked one gets its own panel (SNR mean and min, offset, the V2 statistics, TX loudness, peak, leveller gain, limiting, output fill). Breaks longer than 1.5 s are drawn as breaks. There are no legend boxes over the data: a panel with two lines names them in its axis label (solid mean / dotted min) and each run's colour is the colour of its entry in the run list.
- **Marks**: heard overs (blue shade) and transmitted overs (red shade), key down/up, end-of-over and calls, dial/mode/setting changes. A call is marked as soon as the log has it (from the call event, not the over's row, so a live run shows it mid-over): V1 as a purple line where it arrived, labelled on the top graph; V2 as a small label at the upper left of the over on every graph from the moment it is decoded, and, once the over has ended, a purple line and vertical label at its end.
- **Zoom / pan**: the matplotlib toolbar (magnifier, cross, home/back). *Fit all* shows every run.
- **Measure**: tick it, click A then B: dt, dy and the mean/min/max of every plotted series between them go to the text area. Esc clears.
- **Overs list**: choose one to zoom to it; the text area then gives its static information - run, UTC times, dial, mode, waveform, Invert, the nominal energy centre (dial +/- 1500 Hz), the decoder's offset, SNR statistics, end-of-over, call.
  Choosing a run in the run list shows its `meta.txt` and a summary (dials heard, calls, event counts).

- **Tidying at start**: before anything is opened the viewer runs `tidy_logs.py` on `rade-logs/`: every run directory except the newest is finished (compressed to `<run>.tar.gz`, the copy checked, the directory removed), because a run that piHPSDR did not stop cleanly (killed, crashed) is otherwise left as a directory for good. A recovered run's `meta.txt` gets `ended_utc` (the last file written) and `recovered: 1`. A directory named on the command line, one written to in the last 60 s and one whose copy does not check out are left. By hand: `python3 tools/rade-logview/tidy_logs.py [--dry-run] [rade-logs-dir] [--keep RUN]`. Test: `python3 test/rade_logview/test_tidy_logs.py`.

The old single-file `*_RADE.csv` logs are converted by `convert_old_logs.py` (end-of-over flag and calls were never recorded in them and stay blank). Test: `python3 test/rade_logview/test_logview.py` (window part is withdrawn, nothing appears).
- **Frequency panels** (offset, est_foff) are centred on 0 Hz, at least ±2 Hz, wider only if the data is. A y range you set by zoom or pan is kept when the plot is redrawn by a live update; **Fit all** and **Remove all** forget it.
